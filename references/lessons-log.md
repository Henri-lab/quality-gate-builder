## 架构

### L-001 质量是"门禁"，不是"口号"：每条措施必须自动执行且不可跳过
- 日期：2026-10-15｜来源：设计推理｜档位：任意
- 结论：本地能跑、口头上说"我们会测"都不算数；保护措施的判断标准只有三条——能否在 CI 自动执行、能否触发即阻断、有没有证据。
- 为什么＋落地：把三条标准写进 protection-checklist.md 的验收方式，任何措施答不上来就降级为待办项。

### L-002 压测结论 = 吞吐 + p99 + 错误率 + 资源饱和，缺一不可
- 日期：2026-10-15｜来源：设计推理｜档位：Q2+
- 结论："压出 1 万 RPS"不是结论——p99 爆炸、错误率 5%、数据库连接池打满，说明那 1 万 RPS 是假繁荣。
- 为什么＋落地：load-testing.md 把四类指标并列断言；基线取三次中位数，门禁用容差（p95≤×1.2 等）。

### L-003 模拟支付必须故意制造异常：重复投递/金额不符/伪造/拒付是必测项
- 日期：2026-10-15｜来源：设计推理（对齐 MSP 符合性向量）｜档位：Q1+
- 结论：happy path 全绿只能证明"路径通"；钱相关链路的风险全在异常路径（重放、伪造、拒付），漏测一条就可能在真实渠道下资损。
- 为什么＋落地：simulators.md 把异常剧本直接映射 MSP 的 T-03/04/07/44~46，断言落在账本与权益事实。

### L-004 模拟并发用户要走真实会话，别用后门 token
- 日期：2026-10-15｜来源：设计推理（对齐 ASP）｜档位：Q2+
- 结论：用万能后门 token 模拟用户，等于没测认证链路的真实成本（验证码、会话、限流），并发数也失真。
- 为什么＋落地：UserSimulator 走 ASP 注册/登录，会话生命周期完整；abuse 剧本验证限流是"按设计生效"。

### L-005 测试数据不清理 = 明天的假绿：共享库必须串行化，数据带 run_id
- 日期：2026-10-15｜来源：推理（对齐 engineering-pitfalls 共享库教训）｜档位：任意
- 结论：测试数据残留会让"恰好只发生一次"的断言在下次运行时变假绿；共享测试库并发跑同一套用例会互相顶数据。
- 为什么＋落地：test-pyramid.md §5 数据纪律：自建自清、随机后缀、共享库串行化；压测结束清理订单/账本。
