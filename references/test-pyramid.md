# 测试分层（test pyramid）

> 原则：**快且多**在底层（单元），**慢且少**在顶层（E2E）。钱相关链路（支付/订单/账本）允许倒置一部分——
> 用契约与符合性向量补足，而不是只堆单元测试。

## 1. 四层

| 层 | 测什么 | 工具/做法 | 数量与速度 |
| --- | --- | --- | --- |
| 单元 | 纯逻辑：金额计算、状态机迁移、段回收 | 语言自带测试框架 + table-driven | 多、毫秒级 |
| 集成 | 与真实依赖的边界：SQL 约束、唯一索引、事务 | Testcontainers（真 Postgres/Redis） | 中、秒级 |
| 契约 | 接口行为对齐协议：MSP T 向量、ASP S 向量 | 复用 conformance 的 smoke 骨架 | 中、秒级 |
| E2E | 全链路剧本：下单→支付→权益→退款→争议 | 三个模拟器驱动 | 少、分钟级 |

## 2. 单元层必测清单（会员/支付域示例）

- 金额：整数分、快照不变（INV-1/2）、退款不含尾数（INV-20）；
- 状态机：所有合法迁移 + 所有非法迁移被拒且无副作用（INV-4/5）；
- 续期单调：`max(原到期, now)+周期`（INV-9）；段回收与并集（INV-16/36）；
- 幂等键构造：`(source_event_id, ref)` 复合键的等价性（INV-15）。

## 3. 集成层必测清单

- 唯一/部分唯一索引真的生效（含 NULL 语义，`NULLS NOT DISTINCT` 陷阱）；
- 条件更新并发：并发扣减恰一次成功（T-26）、撞码租约独占（T-37）；
- 迁移：up → 冒烟 → down → up 可重复；旧版本可读新数据（D-5 回滚演练）。

## 4. 契约层：复用既有协议向量

这是本技能与协议技能的最大结合点：

- membership-system-builder 的 `assets/conformance-smoke.sh.tmpl`：T-02/03/04/26/27/33/36/40/52 + D-1；
- identity-system-builder 的 S-01~S-20：注册/登录/验证码/重置/封禁/审计；
- 断言落在**可观测事实**上：账本 `balance == Σ delta`、权益到期时间、发放事实条数，不只看 HTTP 200。

## 5. 测试数据纪律

- 每个用例自建自清（事务回滚或前缀隔离），共享库要串行化；
- 模拟用户/订单用随机后缀（`test-<run_id>`），避免跨运行污染；
- 生产数据**永不**进测试库；测试库不得有真实手机号/密钥。
