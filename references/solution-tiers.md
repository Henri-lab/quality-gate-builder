# 选型访谈与门禁档位（quality tiers）

> 执行本技能的第一步必读。访谈规则（三问 / 保守假设 / 理由要求）的**唯一权威**见
> agent-skills-index 的 `conventions/solution-interview.md`；本文只保留本技能的档位表（Q0~Q3）。

## 1. 访谈（一次问清，≤3 问）

| # | 问题 | 取值（示例） | 用途 |
| --- | --- | --- | --- |
| 1 | **目的** | 新项目起步 / 已有项目补门禁 / 上线前压测 / 长期质量体系 | 档位主轴 |
| 2 | **规模** | 团队人数、目标并发量级、发布频率 | 档位落点 |
| 3 | **硬约束** | CI 平台（GitHub Actions/Jenkins）、技术栈、预算、数据合规 | 修正取值 |

未回答的项按最保守假设处理并在产出中标注"未确认"（规则见 `conventions/solution-interview.md`）。

## 2. 档位矩阵（目的 × 规模）

| 档位 | 目的 | 规模 | 典型配置 | 核心理由 |
| --- | --- | --- | --- | --- |
| **Q0 最小门禁** | 新项目起步 | 个人/solo，低风险 | lint + 单测 + 冒烟（MSP/ASP 关键向量） | 先让"坏代码进不了主分支"成立，成本最低 |
| **Q1 标准门禁** | 已有项目补门禁 | 小团队，正常发布节奏 | Q0 + 集成/契约测试 + 覆盖率门禁 + gitleaks/trivy | 多人协作后，回归与密钥泄露成为现实风险 |
| **Q2 压测流水线** | 上线前压测 | 有真实流量预期 | Q1 + 负载基线 + 阈值门禁 + 三个模拟器 | 支付/订单是钱相关链路，并发与异常路径必须可复现 |
| **Q3 企业级** | 长期质量体系 | 多人/高并发/多环境 | Q2 + 持续性能回归 + 故障注入 + 环境晋升 | 性能劣化是渐进的，靠每次 PR 回归而不是一年压一次 |

三个模拟器从 Q1 开始引入（契约/E2E 用它），Q2 起承担压测流量；支付/订单类项目**至少 Q2**。

## 3. 换档触发器

- 出现一次线上事故（资损/越权/数据污染）→ 立即升一档并补对应门禁；
- PR 合并后回归 bug 频发（>2 次/月）→ 升 Q1；
- 有真实流量预期或做过一次活动预估 → 升 Q2；
- 团队 ≥5 人或出现多环境 → 升 Q3。

## 4. 理由模板

```text
档位：Q2
依据：目的=上线前压测；规模=目标并发 200，双人团队，GitHub Actions
理由：支付/订单链路是钱相关，必须可复现并发与异常路径
为什么不是 Q1：Q1 没有基线阈值，无法回答"上线能扛多少"
为什么不是 Q3：暂无多环境与持续回归需求，故障注入后置
未确认假设：目标并发 200 为预估，压测后以基线为准
```
