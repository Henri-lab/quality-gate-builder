# 技能维护手册（quality-gate-builder）

维护动作四类：追加、合并、提升、废弃。

## 1. 什么时候写

- 门禁被真实事故证明漏检（例：p99 超阈值却没拦住的线上事故）；
- 一个新工具/做法替换旧方案（例：k6 换 Locust 的取舍）；
- 拿到真实基线/并发数据；CI 平台行为变化；
- 用户明确偏好（覆盖率底线、压测频率、预算）。

不写：通用常识、官方文档能查到的、项目机密（密钥/内部拓扑）。

## 2. 怎么写

```markdown
### L-编号 一句话结论（动词开头）
- 日期：YYYY-MM-DD｜来源：真实项目（哪次事故）/ 推理｜档位：Q0~Q3
- 结论：<一句话，能直接指导决策>
- 为什么＋落地：<原因 + 落地，3 行以内>
```

## 3. 去重 / 提升 / 废弃

- 同主题在原条目补充；冲突时新条目覆盖，旧条目标 `[deprecated by L-xxx]`；
- 同主题 ≥2 条或触及不可妥协项 → 提升进对应 reference（blueprint/load-testing/simulators），保留溯源；
- 工具被取代 → 对应段落标 `[deprecated]`，不静默删除。

## 4. 同步与版本

**唯一上游：独立开源仓库（quality-gate-builder）。** `~/.codex/skills/` 为安装副本——编辑只在上游，单向同步（上游 → 安装副本）。

## 5. 自检清单

1. frontmatter `name` 与目录名一致、`description` 能区分场景；
2. SKILL.md 引用文件都存在；3. 无待办标记；4. 新增条目未含机密；5. 副本已同步；
6. 新增原则/概念前查 agent-skills-index 的 `concept-map.md`：已有则引用不复制，新概念先登记权威位置。
7. 决策回填与提升规则见 agent-skills-index 的 `conventions/knowledge-evolution.md`（证据等级：真实反例 > 推理）。
